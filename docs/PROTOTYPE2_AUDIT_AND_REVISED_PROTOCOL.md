# Prototype 2 code audit and revised evaluation protocol

## What this code version does

- Candidate generation uses a native C mutation policy. With the earlier 21-residue seed and `mutation_rate=0.05`, the rounded event budget is one mutation per generated candidate. ARISE chooses a hotspot from past scores; ALE changes mutation-position probabilities. The annealed policy now rises linearly from 0.25 to 0.70 from first to final generation.
- The main ranking objective is now one fixed bounded value: the C sequence-level fitness prior (`c_score`, clipped to [0, 1]). The C bridge calls `evaluate_fitness(..., target=NULL, ...)`, so this is not a target-specific HERV-K Env binding score.
- The old fragment score is a hand-written amino-acid-composition heuristic, not a machine-learning docking model and not a physical free energy. It has arbitrary units and is excluded from candidate ranking. Reports label it accordingly. The correlation tool now calls it a composition heuristic, the current Pareto analysis refuses to treat it as a binding objective, and feature-ablation analysis skips ranking components with zero weight.
- Standalone AutoDock Vina scoring is off by default and has no ranking or tie-breaking role. A Vina output, if someone explicitly opts in to diagnostics, is computational scoring and is never labeled experimental validation.
- Elitism (`preserve_best`) is on by default for both conditions; it protects the best-so-far candidate under the fixed sequence-level prior. It does not guarantee adaptive outperforms baseline under an external docking metric.

## Important limitations to resolve

- The archive includes older generated result files (including a report that labels Vina-only calculations as “validated”). Those files are historical outputs from an earlier code state; they were not regenerated by this audit and must not be presented as results of the revised protocol. Keep them for traceability, but rerun experiments before using a result table or figure in a final ISEF display.

1. **The optimization objective is not target-specific.** Because the C fitness path passes `target=NULL`, ARISE currently learns associations with a sequence-level prior. Do not describe it as learning HERV-K binding hotspots. A target-specific evaluation can only be introduced after choosing a validated-compatible evaluator and defining a no-leakage evaluation protocol.
2. **HybriDock-Pep length support:** The upstream documentation currently states support for 3–19-residue peptides. The existing 21-residue candidates exceed that documented range. Verify the exact installed release/checkpoint support before interpreting its scores; otherwise choose a validated compatible workflow. Do not silently truncate the sequence.
3. **Structure/docking outputs:** A successful pose-generation step and a favorable model score do not establish binding. Inspect retained poses for clashes, target-site consistency, and receptor/ligand preparation; report failed runs and model warnings. The uploaded archive includes older docking outputs and flags every candidate in the old summary as `fraction_initially_clashed=1.0`; re-check what this diagnostic means after clash relief and do not present it as proof the final poses are all invalid or valid without inspecting them.
4. **Search mechanics:** The search uses a single current-best seed per generation, not a conventional multi-parent crossover GA. It should be described as an adaptive mutation search unless additional genetic operators are actually implemented and tested. The C mutation-selection code also had biased amino-acid replacement and repeated mutation-position sampling; this audit fixes those two issues. The explicit `hotspot_only` ablation remains confined to the selected window even when the mutation event budget is larger than that window.
5. **Small mutation budget:** At a 21-residue length and mutation rate 0.05, the rounded budget is one position. This is low-variation search. Treat 0.05 vs 0.10 as a predeclared sensitivity analysis (both rates identically applied to baseline and adaptive), rather than trying rates until adaptive wins.

## Fair comparison protocol

1. Freeze source code, target structure, peptide-preparation method, model/checkpoint, scoring version, search box, sampling effort, and success/failure handling before evaluating the panel.
2. Pair baseline and adaptive runs by random seed: same seed sequence, population size, generation count, mutation rate, objective, and elitism; only mutation-position policy differs. Run multiple independent pairs (target 10 if runtime permits).
3. Do not use Vina scores to optimize, tie-break, train ARISE, or claim validation. Keep the search objective fixed and distinct from the external evaluation.
4. Define one primary external metric in advance. Use HybriDock-Pep only after the 21-residue compatibility question is resolved. Keep the candidate labels blinded during downstream pose review where feasible. Apply the same receptor, binding region, box, sampling settings, and pose filters to all candidate/control groups.
5. Report all candidates and failures, not only top performers. For each seed pair report winner/loss/tie, difference in the external metric, top-k aggregate, sequence diversity, unique candidate count, runtime, and relevant confidence interval/effect size.
6. Include shuffled/composition-matched negative controls if computationally feasible, but describe them as computational controls, not confirmed nonbinders.

## Honest claims

This implementation can test whether adaptive mutation changes the search trajectory and whether its candidates score differently under a compatible independent computational evaluation. It cannot guarantee that adaptive wins every seed, and it cannot prove peptide binding, cell entry, therapeutic activity, or a causal link between HERV-K and ALS. A robust method must be allowed to lose a fair comparison.


## Revised-code smoke test (not a scientific comparison)

After the changes, a 2-generation, population-10, mutation-rate-0.10 smoke test was run for both conditions using seed 616, the same seed sequence, and preserve-best. Both runs completed with standalone Vina disabled and no structure/surrogate scores used for ranking. ARISE had no hotspot in generation 1, so the adaptive run correctly used uniform mutation then; it used the annealed hotspot policy in generation 2 after discovery.

- Baseline best sequence-prior score: 0.469621.
- Adaptive best sequence-prior score: 0.441437.

This tiny run is only an execution check, not evidence about performance. The baseline winning under the fixed sequence-level prior is expected to be possible and is one reason not to claim adaptive always wins. Neither value is a predicted binding affinity.

The integrity suite was rerun after rebuilding the native C library: 43 tests run, 42 passed, 1 skipped. A separate 2-generation smoke run completed in under one second. Rebuild the native code on the target operating system (`make clean && make`) rather than reusing a compiled binary from another platform.

## Bundle notes

The audited archive omits the nested `src.zip` and `full_codebase.txt.zip` snapshots because they contain duplicate, stale code that would contradict the revised source at the repository root. It also omits operating-system-specific compiled C binaries and Python bytecode; rebuild locally with `make clean && make`. The `hybridock-pep/` directory in the original upload does not contain the external HybriDock-Pep implementation, so this bundle does not silently claim to include it. Use the separately installed tool only after verifying checkpoint/version support for the peptide length and documenting its run configuration.
